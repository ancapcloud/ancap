# Контракт OpenClaw и Hermes

Обновлено: 2026-11-04 (v3). Общий источник ролей, расписания и ресурсов. Оба агента читают его в начале цикла и не выходят за свою зону.

## Кто что делает

### OpenClaw — сайт и внешний вид

Для людей и для AI-агентов:

- `frontend-app/` — страницы, вёрстка, тексты интерфейса, состояния экранов, i18n, e2e-тесты Playwright
- публичные файлы, по которым агенты находят продукт: `frontend-app/public/llms.txt`, агентские страницы сайта
- свои записи в `agent-bridge/`
- общий отчёт в Telegram каждые 30 минут (отдельное задание без модели)

OpenClaw не меняет `app/`, `ACP-crypto/`, `ancap-mobile/`, `alembic/`, `tests/` бэкенда.

### Hermes Agent — весь остальной ANCAP

- API (`app/`), схемы, модели, миграции Alembic, тесты `tests/`
- `ACP-crypto/`, `ancap-mobile/`, инфраструктура, CI
- документация и роадмап, кроме текстов интерфейса сайта
- безопасность бэкенда: любой новый изменяющий маршрут — с `require_auth`/`require_platform_admin` и проверкой владельца (см. `tests/test_route_auth_guard.py`)

Hermes не правит JSX/CSS в `frontend-app/`. Если без правки API экран не заработает, Hermes делает API и пишет просьбу OpenClaw в inbox.

## Где каждый работает (без конфликтов git)

У каждого агента своя рабочая копия (git worktree) и своя ветка. Никто не работает в основной папке `Desktop\ANCAP` — это рабочая копия Андрея.

| Агент | Папка | Ветка |
| --- | --- | --- |
| OpenClaw | `C:\Users\drago\Desktop\ANCAP-agents\wt-openclaw` | `codex/openclaw-parallel` |
| Hermes | `C:\Users\drago\Desktop\ANCAP-agents\wt-hermes` | `codex/hermes-parallel` |

Общий канал связи — только `C:\Users\drago\Desktop\ANCAP\agent-bridge\` (абсолютный путь, одна копия на обоих).

Автоматических rebase и merge внутри циклов нет: они могут внести чужие пути и спутать проверку зон. Синхронизацию с основной веткой, проверку совместимости и интеграцию выбранных коммитов выполняют отдельно. Push и deploy — только отдельным разрешённым действием.

## Параллельная работа и ресурсы ПК (v3, 2026-11-04)

Оба агента запускаются одновременно через `agent-bridge/run_parallel.py`, по одному процессу на роль. Новый цикл начинается после завершения обоих и паузы 60 секунд. Лимит процесса 16 минут; повторный экземпляр супервизора блокируется Windows mutex. Файл `agent-bridge/runtime/STOP` останавливает последующие циклы, текущим даётся завершиться.

CPU: 12 логических потоков, RAM: 64 GB, GPU: RTX 5050 8 GB. Один Ollama, одна общая модель `ancap-qwen:9b` (общие веса qwen3.5:9b-q4_K_M); два параллельных запроса, контекст 65536, flash attention, KV q8_0. Не запускать вторую модель. Утилиты сборки получают лимит 4 потока на процесс, модель — 6. Это стартовая конфигурация; фактическую скорость и VRAM смотреть в runtime/ollama.err.log и nvidia-smi. Максимальная загрузка сама по себе не критерий производительности.

OpenClaw: сайт, доступность, локализация, UX и публичные страницы для AI-агентов. Hermes: API, данные, миграции, backend-тесты, mobile, chain, CI и не-UI документация. Общие AGENTS.md, CLAUDE.md, контракт и настройки не редактируют: запрос через inbox. Общие API-контракты согласовывают до реализации. Невлитые зависимости сначала проверяют в коде, затем либо используют, либо берут независимую задачу.

Точечные проверки; полная backend-проверка только перед push/аудитом. Next.js build при необходимости. Никаких самостоятельных push, deploy, merge или внешних сообщений. Telegram-отчёт этим супервизором не включается.

## Как они видят друг друга

| Файл | Кто пишет | Кто читает |
| --- | --- | --- |
| `agent-bridge/CONTRACT.md` | человек / настройка | оба |
| `agent-bridge/status/openclaw.json` | OpenClaw в конце цикла | Hermes и отчёт Telegram |
| `agent-bridge/status/hermes.json` | Hermes в конце цикла | OpenClaw и отчёт Telegram |
| `agent-bridge/inbox/to-openclaw.md` | Hermes | OpenClaw |
| `agent-bridge/inbox/to-hermes.md` | OpenClaw | Hermes |

Статус — короткий JSON без секретов:

```json
{
  "agent": "openclaw",
  "role": "site",
  "branch": "codex/openclaw-parallel",
  "updated_at": "2026-11-04T08:00:00+00:00",
  "status": "completed",
  "task": "что взято в этом цикле",
  "done": "что изменилось",
  "commit": "полный hash или пустая строка",
  "checked": "команда и фактический результат",
  "next": "один следующий шаг",
  "needs_from_other": "просьба другому агенту или пустая строка"
}
```

`status`: `completed`, `partial`, `blocked`, `skipped`. У Hermes `agent` = `hermes`, `role` = `project`, `branch` = `codex/hermes-parallel`.

## Порядок одного цикла

1. Прочитать этот контракт, свой inbox и свежий статус другого агента.
2. Проверить git status и свою ветку; не делать автоматический rebase/merge.
3. Если в inbox есть просьба в своей зоне — сделать её. Иначе взять один маленький шаг своей зоны из начала `MASTER_ROADMAP.md`.
4. Не редактировать файлы чужой зоны. `git add` только своими путями. Запрещено: `git add .`, `reset --hard`, `clean`, `push`, `merge` в master, force-push.
5. Не читать и не записывать `.env*`, `Sicret/`, токены, ключи, seed-фразы, файлы с паролями.
6. Записать свой `status/*.json`. Просьбу другому агенту дописать в конец его inbox, не затирая чужие пункты; выполненный пункт отметить `[x]`.
7. В Telegram сам ничего не отправлять.

## Если зоны столкнулись

Нужен новый экран, а API ещё нет: OpenClaw описывает контракт экрана в `inbox/to-hermes.md` и делает доступную часть вёрстки на заглушке. Hermes закрывает API и отмечает это в своём статусе.

Нужна правка текста или вёрстки из бэкенд-задачи: Hermes пишет пункт в `inbox/to-openclaw.md` и не трогает JSX/CSS.
